# SC-300 Study Guide: PIM Scope, Access Reviews & Group Limitations

## 1. What Does PIM Manage? (The 3 Pillars)

| Pillar | What is Managed | Required License | Key Scope & Onboarding Rules |
| :--- | :--- | :--- | :--- |
| **1. Microsoft Entra Roles** | Built-in & Custom Entra ID roles (e.g., *Global Admin*, *User Admin*, *Security Admin*). | **Entra ID P2** (or Entra ID Governance) | Tenant-wide or Administrative Unit (AU) scope. Enabled out-of-the-box for the tenant. |
| **2. Azure Resources (RBAC)** | Built-in & Custom **Azure RBAC** roles (*Owner*, *Contributor*, *User Access Admin*) at Management Group, Subscription, Resource Group, or Resource level. | **Entra ID P2** (or Entra ID Governance) | **Must be manually onboarded/discovered** per subscription or management group before roles appear in PIM. |
| **3. PIM for Groups** | Just-in-Time (JIT) **Member** and **Owner** assignments for eligible groups. | **Entra ID P2** (or Entra ID Governance) | Groups must be **manually onboarded** into PIM (*Groups -> Select group -> Privileged Identity Management -> Enable PIM*). |

---

## 2. PIM for Groups: Supported vs. Unsupported Groups

> **CRITICAL EXAM RULE:** PIM for Groups ONLY works with **cloud-only, assigned** groups.

| Group Type | Supported in PIM for Groups? | Exam Trap / Notes |
| :--- | :--- | :--- |
| **Assigned Security Groups** | **YES** | Supports both **Member** and **Owner** JIT elevation. |
| **Assigned Microsoft 365 Groups** | **YES** | Supports both **Member** and **Owner** JIT elevation. |
| **Role-Assignable Groups** (`isAssignableToRole = true`) | **YES** | Recommended pattern for assigning Entra roles to a group while keeping JIT activation via PIM for Groups. |
| **Dynamic Groups** (Dynamic User / Dynamic Device) | **NO** | Membership is rule-driven; cannot be manually elevated via PIM. |
| **On-Premises Synced Groups** | **NO** | Must be mastered in the cloud (Entra ID), not synced from Active Directory. |
| **Distribution Lists** | **NO** | Not security principals in Entra ID. |

## 3. PIM Access Reviews Across All 3 Pillars

| Feature | Entra Roles & Azure RBAC Roles | PIM for Groups |
| :--- | :--- | :--- |
| **Where to create** | Inside **PIM** -> *Microsoft Entra roles* (or *Azure resources*) -> *Access reviews*. | Inside **PIM for Groups** -> *Access reviews* (or Identity Governance -> *Access reviews*). |
| **Assignment Types Reviewed** | Both **Eligible** and **Active** assignments. | Both **Eligible** and **Active** Members and Owners. |
| **Inherited Assignments Trap** | If an Entra/Azure role is assigned to a **Group**, reviewing the *Role* will **NOT** review individual users inside that group. You must review the **Group** itself. | Reviewing the group evaluates direct members/owners. |
| **Auto-Apply Results** | If enabled, denied users lose their *Eligible* or *Active* role assignment automatically when the review completes. | Denied users are removed from *Eligible* or *Active* group membership/ownership. |

## 4. Top SC-300 Exam Traps for PIM

1. **The "Double Activation" Trap (Role-Assignable Group + PIM):**
   * If you assign an **Entra Role** as *Eligible* to a **Role-Assignable Group**, and you also enable **PIM for Groups** on that same group where a user is *Eligible* to become a Member:
   * To use the Entra role, the user must perform **TWO activations**:
     1. Activate **Group Membership** in PIM for Groups.
     2. Activate the **Entra Role** in PIM for Entra Roles.
   * *Fix/Best Practice:* Assign the Entra Role as **Active** to the Role-Assignable Group, and manage JIT activation solely via **PIM for Groups** (so the user only activates once).
2. **Global Administrator & Privileged Role Administrator:**
   * Only **Global Administrator** or **Privileged Role Administrator** can manage PIM role settings and assignments for **Microsoft Entra roles**.
   * For **Azure Resources**, managing PIM requires **Owner** or **User Access Administrator** on that Azure subscription/resource.
3. **Permanent Active Assignments:**
   * By default, PIM allows *Permanent Eligible* assignments, and many built-in roles allow *Permanent Active* assignments unless restricted in Role Settings.
   * **Trap:** Even if a user has a *Permanent Active* assignment, it is **not** subject to PIM activation MFA/justification/approval workflows because it is already active!
4. **Classic Subscription Administrators:**
   * PIM **cannot** manage Azure Classic Administrators (*Service Administrator* or *Co-Administrator*). Only standard Azure RBAC roles are supported.
5. **Approval Workflow Trap:**
   * If **Require approval to activate** is enabled on a role, and **no approvers** are selected in the role settings, **Privileged Role Administrators** (for Entra roles) or **Subscription Owners / User Access Administrators** (for Azure resources) become the default approvers.
6. **License Calculation Trap:**
   * Every user who is **Eligible** for a role/group in PIM, or who acts as an **Approver** or **Access Reviewer** for PIM, must be covered by an **Entra ID P2** (or Entra ID Governance) license.
